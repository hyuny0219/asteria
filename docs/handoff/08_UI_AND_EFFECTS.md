## 보상 연출 타임라인 — 신규 제안값
지급/소비 저장 성공 후 연출을 시작한다. 스킵은 연출만 생략하며 보상 연산을 다시 실행하지 않는다. 설정의 연출 간소화를 모든 흐름에 공통 적용.

|흐름|0ms부터 순서|이펙트·사운드|간소화|
|---|---|---|---|
|방치 보상|0–150 배경 딤, 150–350 패널 진입, 350–650 아이템 순차 표시, 650 이후 받기|별 입자 최대12, 부드러운 종1회, 흔들림 없음|150ms 패널 페이드 후 숫자 즉시 표시|
|강화|0–180 금속 링, 180–350 수치 전환, 350–600 테두리 안정|짧은 금속 음, 성공 표식, 흔들림 없음|수치/완료 텍스트 즉시|
|소환·확장|0–300 상자 고정, 300–800 빛 모으기, 800–1100 개봉, 1100–1800 결과, 이후 스킵|등급 최고1회 강조, 묶음 전체 지급, 2px/80ms 1회|300ms 후 결과 그리드|
|승급|0–400 현재 모습, 400–900 장미/금속 문양 전환, 900–1400 새 실루엣, 1400–2200 이름/스킬/보상|저음 상승→종, 별은 배경에만, 3px/100ms 1회|현재/다음 비교 후400ms 새 모습|
|전설 획득·확장|0–200 배경 딤, 200–650 금빛 수직선, 650–1100 아이템/이름, 1100–1500 획득 내역|화면 점멸 대신 단일 광선·벨, 2px/80ms|등급명+아이콘 페이드|
|보스 처치|0–120 적 반응, 120–420 소멸, 420–800 승리 표시, 800–1200 결과|타격음→잔향, 숫자 정리 후 보상|300ms 결과 전환|

사운드 큐는 설계값이다. 기존 motion_sfx.wav는 시연용 합성 효과음만 포함한다. 전용 BGM·최종 보이스·상용 믹싱은 포함하지 않는다. 브라우저에서 오디오는 사용자가 재생/음소거 해제를 선택한 뒤 시작한다.

## 타이포그래피·숫자
- Noto Sans KR 동봉. 본문 16px/1.6, 보조 14px/1.5, 배지 12px/1.4, 제목24px, 이름32px. 중요 정보는 임의 축소 금지.
- 숫자 tabular-nums. 1,000 미만 정수, 1K 이상 1.28K, 1M 이상 1.28M, 1B 이상 1.28B. 999.99K 반올림은 1M으로 승격. 버튼은 전체 비용 확인 가능, 연산은 원래 정수.
- 잠금/등급/강화 결과는 색 + 아이콘/텍스트. 등급은 일반 I / 고급 II / 희귀 III / 영웅 IV / 전설 V / 신화 VI. 장비 재질은 원래 색 유지.
- 움직임 감소 시 흔들림·줌·섬광 제거, 간단 페이드 또는 즉시 변화. 필수 경고는 정적 테두리/문구로 보존.

## 렌더링과 출고 파이프라인
1. 원화 보존 → 개체별 알파 분리 → 얼굴/무기/실루엣 확인 → 포즈 제작 또는 리깅.
2. 384×512 셀, 영웅 발바닥 기준 피벗 통일. 보스는 필요 시 512×640 이상 별도 셀. 투명 여백을 포함한 원본 사각형과 trimOffset, pivot, hitbox를 별도 저장.
3. 2px 이상 패딩·extrude로 패킹. 텍스처 최대2048을 초기 목표로 하되 기기에서 측정. 4096 RGBA 비압축은 약64MiB라는 메모리 비용을 고려한다.
4. UI는 DOM/SVG, 전투는 Canvas. 비도트이므로 imageSmoothingEnabled=true, CSS image-rendering:auto. 정수 확대 강제하지 않는다.
5. Canvas backing size는 CSS 크기×min(devicePixelRatio,2)부터 시작. 리사이즈 후 transform을 reset하여 누적 확대 방지.
6. 큰 원화를 매 프레임 decode하지 않는다. 진입 지역만 선로딩, 전투에서 쓸 크기로 캐시. 배경 탭은 논리 중단·복귀 정산.
7. 실제 모바일 360×700/390×844, DPR1/2/3, 저사양30fps에서 예고/수치/발접지·입력 검수. 데스크톱 Chromium 검증은 실제 모바일 실험을 대체하지 않는다.
8. PNG 알파·경계·폰트 라이선스·파일 해시·용도·출처·미완성 상태를 asset_manifest에 유지한다.
